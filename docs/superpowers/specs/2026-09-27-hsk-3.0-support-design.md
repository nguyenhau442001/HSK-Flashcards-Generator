# HSK 3.0 Support — Design Spec

Date: 2026-09-27

## Updated scope (2026-09-29)

This implementation now uses the newer 2025 HSK exam syllabus dataset,
exported from the official HSK vocabulary endpoint. This update supersedes
the earlier provisional 2021-standard counts and the phased placeholder scope
below. The deck sizes are 300 / 200 / 500 / 1,000 / 1,600 / 1,800 new entries
for levels 1–6, plus one shared 5,600-entry advanced list for levels 7–9.
Levels 7, 8, and 9 keep separate progress storage while loading copies of that
same shared vocabulary list. Source and translation notes are in
`database/vocabs/hsk3_0/ATTRIBUTION.md`.

Examples come from existing local Vietnamese decks and the sentence bank when
an exact match is available. The flashcard hides its example panel when an
entry has no example. Vietnamese meanings outside the local decks are draft
machine translations and need spot review.

## Background

The app models the 2.0 syllabus in HSK1–HSK6 and adds the 2025 HSK 3.0
exam syllabus in a separate version picker. The 2.0 syllabus has 6 levels (
150/150/300/600/1300/2500 words, 5000 total). HSK 3.0 restructures the
syllabus into 9 levels grouped into 3 bands (Sơ cấp 1–3, Trung cấp 4–6,
Cao cấp 7–9). The same Chinese words can occur in both versions, but their
study progress uses separate keys.

Existing HSK1–6 data and progress are left untouched; HSK 3.0 is added
alongside it.

## Scope

**In scope (this spec, full infra):**
- Data schema and file layout for all 9 HSK 3.0 levels.
- `LEVELS`-equivalent config for 3.0 levels.
- Version switcher UI (2.0 / 3.0) inside the existing "Theo cấp độ" vocab
  sub-tab.
- Progress storage keying for 3.0 levels, isolated from 2.0 keys.
- Level picker cards for all 9 levels, wired into the existing
  select/study/progress flow unmodified.

**In scope (data population):**
- Populate all nine exam levels from the 2025 HSK exam syllabus export.
- Keep the shared 5,600-entry advanced vocabulary list available under
  levels 7, 8, and 9, with separate progress keys.

**Explicitly out of scope:**
- Prebuilt TTS audio for 3.0 levels (2.0 pattern of `prebuiltAudioManifest`
  reused as-is; 3.0 levels fall back to Web Speech API like HSK3–6 today).
- Any change to topics, radicals, mini-games, or fast-review — those
  systems key off `LEVELS`/`hskLevelKeys()` and continue working against
  2.0 keys unless explicitly extended later.

## Data Accuracy Caveat

Level membership and pinyin come from the 2025 HSK syllabus export described
in `database/vocabs/hsk3_0/ATTRIBUTION.md`. Some Vietnamese glosses are
machine-translated drafts, and entries without matching local example
sentences omit examples. These are the remaining content review areas.

## Data Layout

New directory, parallel to the existing flat files:

```
database/vocabs/hsk3_0/
  level1_vocabularies.json   (300 words)
  level2_vocabularies.json   (200 words)
  level3_vocabularies.json   (500 words)
  level4_vocabularies.json   (1,000 words)
  level5_vocabularies.json   (1,600 words)
  level6_vocabularies.json   (1,800 words)
  level7_vocabularies.json   (5,600 shared advanced words)
  level8_vocabularies.json   (5,600 shared advanced words)
  level9_vocabularies.json   (5,600 shared advanced words)
```

Levels 1–6 contain the new entries introduced at each level. The syllabus
groups the 5,600 advanced entries under levels 7–9 rather than splitting
them by exam level. `state.js` records these exact counts.

Word object fields match the existing files — `id`, `hanzi`, `pinyin`,
`meaning`, `example_zh`, `example_py`, `expected_pinyin`, `example_vi`.
Example fields may be empty when the local sentence bank has no matching
sentence; `flashcard.js` hides the example panel in that case.

## Config (`assets/js/state.js`)

HSK 3.0 has a sibling config object merged into `LEVELS`:

`LEVELS_HSK30` in `assets/js/state.js` contains all nine available levels with
the counts listed above and points to their JSON files in `database/vocabs/hsk3_0/`.

Keys are merged into the single `LEVELS` object, so shared study and progress
flows use the same configuration lookups for both versions.

`hskLevelKeys()` currently excludes `TOPICS` keys only. It must also
exclude `LEVELS_HSK30` keys, since it drives the 2.0-only learning
dashboard aggregate (`learningProgressSummary` in `levels.js`). A
`hsk30LevelKeys()` counterpart is added for the 3.0 dashboard/picker.
Alternative considered: one combined `hskLevelKeys()` that includes both
and tags entries with `version` — rejected because the dashboard's
"today's goal" / "quick start" logic is meant to track one syllabus at a
time per the approved version-switcher UX, and mixing both would produce
a nonsensical combined progress bar.

Each `LEVELS` entry gains a `version: '2.0' | '3.0'` field (added to
existing HSK1–6 entries too, defaulted `'2.0'`) so shared code (backup
restore, overview) can label which syllabus a card belongs to without
relying on key prefix string-matching.

## Storage Keys

`storageKey()` in `state.js` builds `hsk_<currentLevel>_<suffix>_v2`.
Since 3.0 keys are `hsk30_1`..`hsk30_9` (distinct from `hsk1`..`hsk6`),
their storage keys never collide with 2.0 keys. While the 2025 lists replaced
the provisional 3.0 data, IDs are kept for words with matching hanzi and
pinyin, plus unambiguous same-hanzi matches where the source pronunciation was
corrected. New words receive unused IDs.

`LAST_LEVEL_KEY` (`hsk_last_level_v1`) is shared globally across
versions today. Left as-is: whichever level (2.0 or 3.0) was last
opened is what "quick start" resumes, which is reasonable single-user
behavior and avoids adding a second last-level slot for a first version.

## UI

**Version switcher** — inside the existing "Theo cấp độ" sub-tab
(`screenPicker`), above the level grid: two small toggle buttons "HSK
2.0" / "HSK 3.0", same visual pattern as `vocabSubTabLevel`/`Topic`.
New JS state `pickerVersion` ('2.0' default), new function
`setPickerVersion(version)` that toggles which level-grid block is
visible and re-renders progress bars for that block.

Two level-grid blocks live in `screenPicker`: the existing HSK1–6 grid and
a 9-card HSK 3.0 grid rendered from `LEVELS_HSK30`. All nine cards are
selectable. Cards 7–9 identify the shared advanced vocabulary list.

`renderLevelProgress()` in `levels.js` already iterates
`Object.keys(LEVELS)`, so it will automatically pick up and paint
mastery bars for the new `hsk30_*` cards with zero changes.

`learningProgressSummary()` / `renderLearningDashboard()` continue to
use `hskLevelKeys()` (2.0 only) so the homepage daily-goal dashboard
stays scoped to whichever syllabus is primary; no dual-dashboard is
built in this phase.

## Testing

- `python3 -m http.server 8000`, load `flashcards.html`, verify:
  - Existing HSK1–6 cards and progress render unchanged (regression
    check — no visual/behavioral diff).
  - Version switcher toggles between 2.0 and 3.0 grids.
  - HSK 3.0 levels 1–6 open with the 2025 syllabus list counts, pinyin,
    Vietnamese meanings, optional examples, and isolated progress storage.
  - HSK 3.0 levels 7–9 each open the shared 5,600-entry advanced list while
    keeping their progress keys separate.
  - Backup/restore JSON export includes 3.0 progress and round-trips.
- `git diff --check` for whitespace issues.
- No build/typecheck tooling in this repo (static JS); manual browser
  verification is the verification step.
